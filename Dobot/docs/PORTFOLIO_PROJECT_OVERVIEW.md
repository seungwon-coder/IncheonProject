# PLC·Vision 연동형 다중 Dobot 생산 자동화 시스템

## 프로젝트 개요

인천인력개발원 `로봇활용 첨단생산시스템 전문가 양성과정`에서 수행한 8인 팀 프로젝트입니다.
PBV 차량의 시트·램프·바디 조립 공정을 축소 구현하고, Mitsubishi PLC와 웹캠 기반
Vision 판정 결과에 따라 Dobot Magician 4대가 조립·분류·불량 회수·부품 재공급 작업을
수행하도록 구성했습니다. KEPServerEX와 OPC UA를 이용해 PLC, Robot PC, Vision,
SCADA 사이의 상태와 공정 데이터를 연결합니다.

## 담당 역할

- 팀장으로서 일정과 업무를 조율하고 장치 간 인터페이스와 통합 시운전을 지원했습니다.
- 로봇 제어를 주 담당으로 맡아 Dobot 4대 연결, 티칭, 공정 실행, 상태 관리와 오류 복구를 구현했습니다.
- PLC 관련 자격 지식을 바탕으로 래더 시퀀스, 인터록과 로봇 핸드셰이크 검증을 지원했습니다.
- Vision 알고리즘은 팀원이 담당했으며, 판정 결과가 PLC와 로봇 공정에 연결되는 조건을 검토했습니다.

## 시스템 흐름

1. SCADA가 주문 정보를 KEPServerEX 태그에 기록합니다.
2. PLC가 센서와 주문 정보를 읽고 제품을 Vision 검사 위치까지 이송합니다.
3. 웹캠은 계속 영상을 제공하며, PLC START 신호가 들어오면 Vision 판별 프로그램이 현재 영상을 검사합니다.
4. Vision이 OK·NG 결과를 KEPServerEX에 기록하고 PLC가 인터록과 후속 공정을 결정합니다.
5. Robot PC가 PLC의 START와 공정 조건을 읽어 해당 Dobot의 작업을 실행합니다.
6. Robot PC는 RUNNING·FINISH·ERROR·READY와 로봇 좌표를 PLC·SCADA에 전달합니다.

## 로봇 제어 핵심 설계

### 개별 오류 격리

각 Dobot은 독립 Worker 프로세스와 명령 대기열을 사용합니다. 한 로봇의 통신 지연이나
오류가 발생해도 다른 로봇의 상태 조회와 제어를 계속할 수 있습니다.

### 안전 정지

알람, 시간초과 또는 좌표 미변화를 감지하면 해당 로봇의 JOG와 이동 큐를 정지하고
남은 명령을 삭제합니다. 실행 여부를 확신할 수 없는 이동 명령은 자동으로 재전송하지 않습니다.

### 제한적 자동복구

PING, 장치 정보, 상태 조회처럼 실제 움직임이 없는 명령만 Worker 재시작 후 한 번 재시도합니다.
PTP, JOG, HOME과 엔드이펙터 명령은 중복 동작을 방지하기 위해 자동 재실행하지 않습니다.

### 검증 후 재가동

오류 원인을 제거하고 해당 로봇의 HOME과 사용자 READY 위치 복귀가 성공한 경우에만
PLC ERROR를 해제하고 READY 상태로 전환합니다. 필수 티칭 포인트가 없으면 자동운전을 차단합니다.

## PLC 핸드셰이크

| 신호 | 방향 | 의미 |
|---|---|---|
| START | PLC → Robot PC | 공정 시작 요청 |
| RUNNING | Robot PC → PLC | 로봇 작업 중 |
| FINISH | Robot PC → PLC | 공정 완료 |
| ERROR | Robot PC → PLC | 오류 발생 |
| READY | Robot PC → PLC | 다음 공정 실행 가능 |

START는 상승 에지에서 한 번만 처리합니다. FINISH는 완료 시점부터 약 1초간 유지하고,
실행 중 들어온 다음 START는 로봇별로 최대 한 건만 예약하여 중복 기동을 방지합니다.

## 주요 문제 해결

- COM 포트가 변경되어도 저장된 시리얼번호로 동일한 Dobot을 찾아 설정을 복구합니다.
- 로봇별 독립 Worker로 한 대의 응답 지연이 전체 제어에 전파되는 것을 막습니다.
- START의 변화 시점을 구분하여 신호가 계속 ON인 경우의 반복 기동을 방지합니다.
- 통신 단절 시 오래된 좌표를 다시 전송하지 않고, 제어와 좌표 전송의 장애 영향을 분리합니다.

## 검증 방법

- `tests/`: 실제 장비 없이 상태 전이, 통신 계약, 티칭 경로와 오류 처리를 검증하는 자동시험
- `manual_tests/`: 실제 Dobot의 연결, 식별, JOG, PTP, HOME과 통합 공정을 단계별로 확인하는 시험
- 실제 이동 시험은 저속으로 수행하며, 주변 간섭과 비상정지 준비를 확인한 뒤 `--execute` 옵션을 사용합니다.

자동시험 결과와 실제 장비 시험 결과는 구분하여 기록합니다. 실제 설비의 안전성, 정확도와
반복성은 최종 티칭, PLC 래더 검증, Vision 조건별 시험과 전체 연속운전 결과로 확인합니다.

## AI 활용 개발 방식

AI 기반 바이브 코딩을 반복 코드 작성, 오류 원인 분석, 구조 개선과 주석 작성에 활용했습니다.
로봇별 독립 Worker, 상태 머신, PLC 핸드셰이크와 오류 복구 조건은 실제 공정 요구사항을 바탕으로
직접 정의했습니다. 생성된 코드는 동작 원리를 검토하고 자동시험과 실제 Dobot 통신 시험을 통해
검증한 뒤 적용했습니다.
